After several months in public beta testing, we are proud to announce our biggest update yet -- a complete version 1.0. We have listened to all  your feedbacks. The first sharp version provides easy first steps for new users, complex teams and alerts managments for advanced users and all that while keeping true to our privacy-first principle promise.

## What is Radegast EDR?

Radegast EDR (short for [Endpoint Detection Response](https://en.wikipedia.org/wiki/Endpoint_detection_and_response)) is a privacy-first suite that can detect and kill cyber threats on your machines. Unlike other commercial EDRs, Radegast EDR is fully free and open-source. Its main goal is to be super-simple for anybody to deploy without as much complexity as required, while keeping all your data strictly yours. You can read more about our philosophy in our [Designing a Privacy-First EDR Platform](/blog/2026/05/31/designing-privacy-first-edr/) post. 

## New features in v1.0.0

There were lots of small fixes and improvements here and there and listing them all would produce a really exhausive list. The main focus was on making the UX of the whole Console as intuitive as possible for anyone. In either case, there were some bigger features that came along the way. 

### mac Support

Along with already present support for Linux and Windows OSs, we have also added the support for the third major desktop OS. Now you can install Radegast agent and rustinel to you device with our one-command installer.


### Agent healthcheck

Besides only reporting Online/Offline status in your Console, you can now also see if the agent does actually run the detections you have configured. This is done by the agent injecting a testing rule and watching if the testing rule triggers within specified time. If it does not, the device reports as unhealthy in the Console. This usually can mean that rustinel is not running properly, it was either stopped or, in case of a very low-end machine, is overloaded with the number of events and rules configured.

### Active response

Getting to the R part in EDR, if you are running in the [Extended EDR](https://docs.radegast.app/user-guides/settings#extended-edr-mode) mode, inside device group setting your will find [Active response](https://docs.radegast.app/user-guides/groups#active-response-settings). After selecting a severity, any time a new alert will come that has selected severity or higher, the responsible process will be killed immediatedly. This could potentionaly cause service distruption by killing legitimate processes, hence it is hidden behind the extended EDR switch.

### E2EE exclusions

We are actively searching how we can collect *less* data about the users. This time, we have found out that with little clever engineering we can fully encrypt all your detection exclusions. The main downside is that when a new device is added to a device group, *somebody* needs to give it access to the exclusions encryption key. This means that for E2EE exclusions to work properly, after installing a new device, you need to keep your browser window open so that the encryption keys are transffered properly and the agent halts sending alerts for 5 minutes after first installation, which is a small price to pay for less data in the open.

### rustinel auto-updater

The EDR engine we are using, [rustinel](https://github.com/Karib0u/rustinel), is the one component that needs to run as root on your device. Because of that, we take its security very seriously. We have actively sent [upstream patches](https://github.com/Karib0u/rustinel/pull/275) to increase supply-chain security, but we want more control over how this critical piece gets updated on your machine. We have started [PGP-signing](https://radegast.app/api/rustinel-releases.json) all rustinel releases and create a [small separate binary](https://github.com/radegast-edr/radegast-rustinel-updater) that is able to take care of updating the rustinel.
