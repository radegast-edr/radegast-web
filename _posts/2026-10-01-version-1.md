After several months in public beta testing and over 1 million processed alerts, we are proud to announce our biggest update yet -- a complete version 1.0. We have listened to all your feedback. This first stable release provides easy first steps for new users and advanced team and alert management features, all while keeping true to our privacy-first principles.

## What is Radegast EDR?

Radegast EDR (short for [Endpoint Detection and Response](https://en.wikipedia.org/wiki/Endpoint_detection_and_response)) is a privacy-first suite that detects and neutralizes cyber threats on your machines. Unlike other commercial EDRs, Radegast EDR is fully free and open-source. Its main goal is to be as simple as possible to deploy, without the complexity typically required, while keeping all your data strictly yours. You can read more about our philosophy in our [Designing a Privacy-First EDR Platform](/blog/2026/05/31/designing-privacy-first-edr/) post. Alternatively, you can see our [quick-start guide](https://docs.radegast.app/quickstart), jump straight to the [Console](https://console.radegast.app/), or even self-host your own instance in a few seconds using the provided [podman-compose file](https://github.com/radegast-edr/radegast-console-backend/blob/main/podman-compose.yaml).

## New features in v1.0.0

There have been numerous small fixes and improvements across the board. Listing them all would produce a lengthy exhaustive list. The main focus was on making the Console UX as intuitive as possible for everyone. That said, several major features also made their way into this release. 

### macOS Support

Along with the existing support for Linux and Windows, we have now added support for the third major desktop OS. You can install the Radegast agent and rustinel on your device with our one-command installer and pick up the detection packs, just as you would for any other OS. Now there is nothing stopping you from protecting all the devices you want.

### Agent Health Check

Beyond simply reporting Online/Offline status in your Console, you can now verify whether the agent is actually running the detections you have configured. The agent does this by injecting a test rule and checking if it triggers within a specified time. If it does not, the device reports as unhealthy in the Console. This typically means that rustinel is not running properly -- it may have been stopped, or on very low-end machines, it may be overloaded by the number of events and configured rules.

### Active Response

Getting to the R in EDR: If you are running in [Extended EDR](https://docs.radegast.app/user-guides/settings#extended-edr-mode) mode, you will find [Active Response](https://docs.radegast.app/user-guides/groups#active-response-settings) in the device group settings. After selecting a severity threshold, any time a new alert arrives at that severity or higher, the responsible process will be killed immediately. This could potentially cause service disruption by killing legitimate processes, which is why it is hidden behind the Extended EDR switch.

### E2EE Exclusions

We are actively exploring ways to collect *less* data from users. This time, we have found that with some clever engineering, we can fully encrypt all your detection exclusions. The main downside is that when a new device joins a device group, *somebody* needs to give it access to the exclusions encryption key. This means that for E2EE exclusions to work properly, after installing a new device, you need to keep your browser window open so that the encryption keys are transferred properly. The agent also halts sending alerts for 5 minutes after first installation -- a small price to pay for keeping less data exposed.

### rustinel Auto-Updater

The EDR engine we use, [rustinel](https://github.com/Karib0u/rustinel), is the one component that needs to run as root on your device. We therefore take its security very seriously. We have actively contributed [upstream patches](https://github.com/Karib0u/rustinel/pull/275) to improve supply-chain security, but to properly follow industry best practices (like time-delay), more control over how this critical piece gets updated on the endpoint is needed. We have started [PGP-signing](https://radegast.app/api/rustinel-releases.json) all rustinel releases and created a [small separate binary](https://github.com/radegast-edr/radegast-rustinel-updater) that handles rustinel updates, significantly lowering the possible attack vector.

## Where We Go Next

Version 1.0 is definitely not the last release -- it is simply the first release we are comfortable with sharing with the world. There are still many things we can improve. For one thing, new cyber threats never stop appearing, so we will work hard to keep the detection rules up-to-date. One other thing is the distribution of the agent, which is now installed as part of the single command. For advanced users, we want to offer an option to obtain the agent as they would any other software, from `apt`, `yum`, `brew`, `winget`, or any other popular package manager. Of course, there is also the never-ending work of minor UX updates based on our interactions with the Console and your feedback (thank you all for that!), infrastructure upgrades... The list could go on, so stay tuned for updates.
